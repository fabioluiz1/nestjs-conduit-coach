# Q02 — Story → technical change (validated submissions)

## Question (as asked)

The second story: the app **rejecting invalid submissions**.

> *As an author, when I submit an article with an empty title or body, the app rejects it with a
> clear, field-level error, so I know exactly what to fix.*

Name the technical change it requires, explain why the story demands it, and name the file(s) that
prove the gap.

## Candidate's answer

It requires adding `@IsNotEmpty` validations to the DTO:
`backend/src/article/dto/create-article.dto.ts`.

Then we need to wire `backend/src/shared/pipes/validation.pipe.ts` to the actions using that DTO:
create and update [handlers of `backend/src/article/article.controller.ts`].

We can attach the validation pipe through the `@Body('article', [validationPipe])` annotation;
however this would introduce a new coding pattern — existing code uses
`@UsePipes(new ValidationPipe())` (`src/user/user.controller.ts`). Which one to use can be recorded
as a Decision.

## Coach pushback + resolution

**Pushback 1 — name the second proof file.** Candidate initially named only the DTO. Coach: the
story also fails because nothing *runs* the validation — which file holds the create/update
handlers and what's absent? **Candidate corrected:** `article.controller.ts` — `create` and
`update` bind `CreateArticleDto` with no `@UsePipes`. Gap proven on both ends: DTO has no
decorators, handlers run no pipe. ✅

**Pushback 2 — Decision vs DoD.** Candidate first proposed deferring the pipe-attachment style to a
DoD/code-review item. Coach: the repo already picked the pattern (`user.controller.ts` uses
`@UsePipes`), so it's a **Decision made now by precedent**, not a deferred review item; Code Quality
3-star = "follows existing patterns exactly," so the `@Body`-param style would be a divergence ding.
DoD is reserved for reversible debt in this diff that must be cleared before submit — it must
*clear* something. **Candidate landed on:** Decision = use `@UsePipes` (aligned with existing code).
Coach final correction: the rejected `@Body`-param pipe is the **"alternative considered" field of
that Decision**, not a separate DoD line — nothing goes on the DoD list here.

**Pushback 3 — candidate reopened: argued the alternative should be a DoD item asking reviewers for
consensus on expanding the pattern, framing the extra `@UsePipes` import as technical debt.** Coach:
the debt framing is inverted — one import that matches every validated handler is *consistency*;
the real debt is two different ways to wire validation in one codebase. A DoD item must be
*clearable by the candidate before submit* — "get reviewer consensus" can't be checked off in a
solo timed exam, so it fails the definition. The senior instinct (surface the divergence, invite
review) belongs in the Decision's **"alternative considered"** line, phrased as an open invitation,
and in real life a PR review comment — not the DoD list. **Candidate agreed and settled:** its home
is "alternatives considered," not the DoD list.

## Coach verdict

**3-star derivation** after three pulls. Correct change (`@IsNotEmpty()` on the DTO + repo's own
`ValidationPipe` via `@UsePipes` on create **and** update), both proof files named
(`create-article.dto.ts`, `article.controller.ts`), and the pipe-style choice correctly classified
as a single Plan Decision with a stated rejected alternative.
