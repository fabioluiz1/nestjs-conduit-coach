# Q03 — Entity change vs DB (data model: entity vs DB)

## Question (as asked)

You change `Article.body` from `@Property({ fieldName: 'body' })` to
`@Property({ type: 'text', fieldName: 'body' })` in `article.entity.ts` and restart the backend.
Does the MySQL column actually change? Yes or no — and exactly why? (You gestured at this in Q1.
Make the mechanism explicit now.)

## Candidate's answer

No, because the database only changes if a migration file exists and is registered in the
`migrationsList`.

## Coach grade

Correct — **No**. Sharpened the *why* so it's airtight: the entity decorator is only MikroORM's
declaration of the **desired** shape — there's no auto-sync, so it never touches MySQL on its own.
The column type changes **only when a migration's `ALTER` DDL actually executes**. The
`migrationsList` registration is *how* you make that DDL run on boot — that's Q4's territory.

**3-star.**
