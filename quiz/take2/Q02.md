# Q02 — Story → technical change (validated submissions)

## Question (as asked)

> *As an author, when I submit an article with an empty title or body, the app rejects it with a
> clear, field-level error, so I know exactly what to fix.*

Name the technical change this story requires, explain why the story demands it, and name the
file(s) that prove the gap.

## Candidate's answer

It requires adding `@IsNotEmpty` validations to the DTO:
`backend/src/article/dto/create-article.dto.ts`.

Then we need to wire `backend/src/shared/pipes/validation.pipe.ts` to the actions using that DTO:
create and update [handlers of `backend/src/article/article.controller.ts`].

We can attach the validation pipe through the `@Body('article', [validationPipe])` annotation;
however this would introduce a new coding pattern — existing code uses
`@UsePipes(new ValidationPipe())` (`src/user/user.controller.ts`).

The existing pattern is chosen, but I want to document `@Body('article', [validationPipe])` was
considered as a coding alternative.

## Coach pushback 1

3-star on the mechanics — named the repo's own pipe at `shared/pipes/validation.pipe.ts` (the
gotcha), caught that **both** create and update bind the DTO, and surfaced the inline-binding
alternative vs `@UsePipes` (the extraction-vs-binding distinction). One thing to connect back to
the story: which fields, specifically, get `@IsNotEmpty()` — and which do you leave alone?

## Candidate's response to pushback 1

`readonly title: string;` and `readonly body: string;`

## Coach grade

**3-star, complete.** `title` and `body` get `@IsNotEmpty()`; `description` and `tagList` stay
untouched. That scoping matters — decorating `description` would reject valid articles with an empty
description (over-validation = a Correctness ding). Held the line to exactly what the story demands.
