# Q11 — Frontend runtime decoder: required field the backend doesn't send

## Question (as asked — cleaned mid-session to remove a pitfall)

**Frontend-only.** The frontend keeps its own `Article` interface + `articleDecoder`
(`frontend/src/types/article.ts`), separate from the backend. You add `subtitle` to the frontend
`Article` interface and declare it **required** (`subtitle: string`) in `articleDecoder`. The backend's
JSON doesn't include `subtitle` yet. A page calls `getArticles()` and loads. What happens at runtime,
and why? Then: the fix, and the debt it creates.

## Pre-question correction (candidate's first reply went backend)

Candidate initially routed to the backend (`IArticleRO`, `ArticleDTO extends EntityDTO<Article>`, the
entity) and asked whether "Article interface" meant the entity. Coach verified `frontend/src/types/article.ts`
(interface `Article` + `articleDecoder: Decoder<Article>`) — `articleDecoder` is frontend-only
(`decoders`, Concept 7); the backend's `IArticleRO` is a separate type. **Candidate then flagged the
question wording as a pitfall** (the "backend doesn't return it" clause + 70%-backend priming pulls you
to `article.interface.ts`). Coach conceded — fixed Q11 to set the ground (frontend-only) and added a
VOICE rule: disambiguate same-named BE/FE artifacts up front.

## Candidate's answer

Runtime: an error raises because the backend doesn't include `subtitle` and decoder validation fails.
Fix: add `subtitle` to the Article *entity*, create + register the migration, restart — then the API
returns it. However, the field can't be required because existing articles have empty subtitles, which
would also raise errors → it must be optional.

## Coach correction

Runtime ✓ (`articleDecoder.verify` throws on the missing required field). But: (1) a required `string`
decoder accepts `""` — only `null`/`undefined`/missing breaks it, so "empty subtitle" ≠
"decoder-breaking"; whether required works for old rows depends on the migration's null/default choice.
(2) Two distinct reasons for `optional` — **(A)** temporary (frontend ahead of backend → DoD debt,
tighten later) vs **(B)** permanent (domain-optional / nullable rows → no debt).

## Candidate's landing + meta-flag

Candidate: since it's frontend-only, it's **(A)** — and flagged that the coach **ghostwrote** by laying
out the A/B table instead of re-anchoring ("frontend-only → your backend fix is off-side; what's *your*
fix?") and pulling. **Coach conceded the violation** → added a VOICE sub-rule under "never ghostwrite"
(wrong-frame → re-anchor, don't validate-then-explain) and updated the `coach-never-ghostwrite` memory.

## Grade

**3-star** on the resolved answer (runtime throw → frontend `optional(string)` → DoD line to tighten
