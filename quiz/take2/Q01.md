# Q01 — Story → technical change (long-form articles)

## Question (as asked)

> *As an author, I can write an article whose body runs longer than today's 255-char limit, so a
> full post isn't cut off.*

Name the technical change this story requires, explain why the story demands it, and name the file
that proves the gap exists today.

## Candidate's answer

Long form articles requires TEXT (64KB) or MEDIUMTEXT/LARGETEXT columns, otherwise their contents
will cut off.

Medium posts can be small; however their audience may demand longer / elaborated contents that fit
better in TEXT columns. A 64KB size seems good enough for a blogging platform.

We can confirm the gap exists in the `backend/src/migrations/InitialMigration.ts` file:

```
'create table `article` (`id` int unsigned not null auto_increment primary key, `slug` varchar(255) not null, `title` varchar(255) not null, `description` varchar(255) not null, `body` varchar(255) not null, ... ) default character set utf8mb4 engine = InnoDB;',
```

Both description and body are limited to 255 chars which may not be enough.

To change the column size, edit the entity file `backend/src/article/article.entity.ts`:

```
@Property({ fieldName: 'body' })
body = '';
```

to

```
@Property({ type: 'text', fieldName: 'body' })
```

OPTIONAL: adjust `description` to a bigger size (not 255; but not text — 1024 may be a better fit).
PRO: simple adjacent change; CON: scope creep.

To make the change effective: `npx mikro-orm migration:create` → creates a new file in
`backend/src/migrations`. Register it in `backend/mikro-orm.config.ts`'s `migrationsList`. The
migration runs by `npx mikro-orm migration:up`, or by rebooting the app because
`backend/src/app.module.ts` invokes `getMigrator().up()`.
