# Q07 — Auth middleware wiring (already protected + new route)

## Question (as asked)

Confirm the create/edit routes are already auth-protected, and name where. And: if you added a
brand-new article sub-route that needed protection, which file and which method call would you add it
to?

## Candidate's answer

Yes — protected in `backend/src/article/article.module.ts`:

```
{ path: 'articles', method: RequestMethod.POST },
{ path: 'articles/:slug', method: RequestMethod.PUT },
```

`configure` injects `AuthMiddleware` into the request handler via a `MiddlewareConsumer`. The new
protected route is appended to the `forRoutes(...)` list, e.g.
`{ path: 'articles/brand/new/sub/route', method: RequestMethod.XXX }`.

(Candidate verified against the real file — `article.module.ts:27`,
`{ path: 'articles/:slug/favorite', method: RequestMethod.DELETE }`.)

## Coach grade

**3-star.** Correct and verified against source. Sharpened the mechanism by one notch: the module
implements `NestModule`, so Nest calls its `configure(consumer: MiddlewareConsumer)` at startup, and
`consumer.apply(AuthMiddleware).forRoutes(...)` binds the middleware onto exactly the listed
(protected) routes — selective, not all-or-nothing. A new protected route is one more entry in that
same `forRoutes(...)` chain.
