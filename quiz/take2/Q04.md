# Q04 — Migration registration gotcha

## Question (as asked)

You write `backend/src/migrations/AlterArticleBodyDescriptionToText.ts` with the correct
`ALTER TABLE` DDL. You restart the backend. The migration does not run. What's missing, and in
which file? And name the *reason* the repo requires that step, rather than discovering the file on
its own.

## Candidate's answer

The database only changes if a migration file exists and is registered in the `migrationsList`. It
doesn't auto-discover because `discovery: { disableDynamicFileAccess: true }`. We prefer manual
registration for a reason: in AWS Lambda the migration files won't survive into the bundled
deployment — there will be no file to auto-discover. We list them in `migrationsList` so MikroORM
knows the full set and runs the pending ones.

## Coach grade

**3-star** — gave the deep reason, not just the surface one. `disableDynamicFileAccess: true` kills
glob discovery; MikroORM only knows what's hand-listed in `migrationsList` (in
`mikro-orm.config.ts`). The architectural payoff: bundle-safe deploys — under a bundler
(Lambda/Vercel) the migration files get inlined and the folders vanish, so there's nothing to glob.
Explicit registration survives bundling.
